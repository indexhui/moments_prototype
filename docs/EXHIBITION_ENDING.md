# 展覽版結尾

Figma 來源：[結束的流程](https://www.figma.com/design/9ased7HFhhFpvVNl3WPrdK?node-id=12910-16423)。

遊玩到 `home-final` 最後一句後，進入 `complete`：四張照片回顧 → 撕抽獎券 → 獎品 → 感謝與事前登錄。沿用展覽版中間的手機舞台與 Menu。

## 照片

依順序使用本局黃金獵犬、街道青蛙、便利商店青蛙、甜點店青蛙的 `framePreviewUrl` 與 `score`。四張照片由本次劇情狀態提供，並分開寫入 sessionStorage 供劇情重新整理時還原。照片依序滑入、輕轉落定，接著貼上膠帶、展現照片光澤與星等。星等為 90% 以上三星、70% 以上兩星，其餘一星。跳轉測試而未實際拍照時使用既有角色預覽圖，不虛構分數。

## 抽獎庫存

- A 2 組：夏日、煙火明信片各一張。
- B 3 組：煙火明信片。
- C 3 組：夏日明信片。
- D 100 組：黃金獵犬貼紙。

每一組剩餘獎品具有相同抽中機會。正式流程在撕券時抽出並儲存，庫存與抽獎扣款防重紀錄寫在同一份 localStorage 紀錄；結尾不會讀取前次結果來跳頁。採 Web Locks 序列化同瀏覽器分頁的操作，需使用支援 Web Locks 的現代瀏覽器與 localhost / HTTPS。

每次完成劇情、重新整理結尾，或選擇「重新播放結尾」，都從四張照片重新開始，再走完撕券、獎品與感謝頁。結尾頁面狀態不儲存，抽獎每次使用新的識別碼；僅同一次撕券的重複請求不會重扣庫存。抽完 108 組顯示送完提示，仍可進感謝頁。儲存失敗時不發出未記錄的獎品。

Menu → 特殊選項 → `2026`，可查庫存及 Reset。Reset 確認後恢復 2／3／3／100，保留已抽出的結果。密碼是單機展覽的操作入口，並非伺服器驗證。

重新開始、從標題開始下一位玩家會建立新局並清除本局照片，保留獎品庫存與 Email 名單。資料依裝置、瀏覽器、網站來源（包含 port）區分；清除瀏覽器資料會清除庫存與名單。

右側開發工具原有的「抽獎券」仍是可重玩的視覺預覽，不扣正式庫存。

## Steam 與事前登錄

Steam 區塊只顯示「Steam 搜尋」與醒目的遊戲名稱「走走小日」，邀請玩家加入願望清單，不提供點擊連結；連結由現場 DM 提供。感謝文案採「謝謝您的遊玩」與禮貌稱呼。

早期預約填寫名稱（暱稱，必填、最多 40 字）與 Email，經驗證與玩家同意後先存於此裝置。相同 Email 不重複加入，重填可更新暱稱。既有未填暱稱的名單仍可讀取。特殊選項可匯出含暱稱的 UTF-8 CSV。獎品 Reset 不清除 Email。尚未接遠端 API 或寄信服務；之後將 `registerExhibitionEmail` 換成正式串接。

## 驗證

`node --test scripts/exhibition-ending.test.cjs` 涵蓋庫存耗盡、抽獎權重、連點與重整、Reset、跨玩家隔離、照片還原、儲存失敗及重複 Email。`npm run build` 驗證正式版編譯。

直接檢視結尾：`/game/exhibition?preview=complete`。每次進入此入口都完整重播結尾；獎品庫存持續保留。
