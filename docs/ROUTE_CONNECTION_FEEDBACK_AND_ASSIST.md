# 路線接通回饋與甜點店小貝狗協助

更新：2026-09-27。此文件記錄本次確認的最終行為與視覺，後續調整以此為準。

## 範圍

- 一般直線路線：`StorySimpleMetroRouteView.tsx` 的共用 `StoryLinearRoutePuzzleStage`，涵蓋單格／雙格直線關卡。
- 甜點店：`StoryDessertShopMechanismRouteView.tsx` 的六格滑動道路拼圖。
- 不包含其他獨立網格、轉彎或小遊戲元件；這些元件不會自動套用直線關卡的完成演出。
- 繁中、英文、日文皆有對應文字。

## 一般直線路線

玩家放對最後一塊後，自動進入以下流程，不需先按出發才知道已接通：

1. 關閉道路間隙，鎖住拼圖操作；包含起點、終點的整條路由下往上依序亮起。
2. 整條路輕微亮起，下方拼圖選擇區改成「路線已接通」完成提示。
3. 提示淡出，出現唯一的大型「出發 →」按鈕及次要「重新安排」入口。
4. 按出發後才執行既有存檔、行程轉場與事件流程。完成演出本身不視為已出發。

「重新安排」清空可放置的格子，回到排列階段，恢復拼圖庫與原本教學／操作區。出發後停用按鈕，避免重複送出。

### 最終節奏

| 階段 | 時間 |
| --- | --- |
| 道路收攏 | 260 ms |
| 相鄰圖塊亮起的起始間隔 | 90 ms |
| 每塊亮起 | 300 ms |
| 完成提示 | 700 ms |
| 出發按鈕淡入 | 160 ms |

亮路結束時間為 `260 + (slotCount + 1) × 90 + 300` ms。雙格關卡從接通到出現出發按鈕約 **1.53 秒**；單格約 **1.44 秒**，其後按鈕短暫淡入。不要恢復成原本約 2.5 秒的等待。

### 最終視覺

- 接通後仍保留奶油色底板、圓角及細棕框，道路內部無縫相連；不要只剩裸露的長條道路。
- 使用柔和的逐格提亮與淡色光暈，避免大面積刺眼黃色外框。
- 底部完成區高 136 px，以暖白底、綠色勾選圓形、深棕文字呈現。
- 出發是大面積棕色圓角按鈕，有明確底色與按壓回饋；「重新安排」為次要動作。
- 完成後不再同時保留原本底部的出發按鈕。
- 支援減少動態效果偏好；保留完成到出發的兩階段狀態。

## 通勤關卡沒有拼圖地點順序限制

`morning-route` 只以兩格填滿及所有道路寬窄接頭相連判定完成。以下兩種由上往下的盤面都成立：

- 公司 → 街道寬接寬 → 捷運寬接窄 → 家。
- 公司 → 捷運寬接窄 → 街道直路 → 家。

**不可用街道與捷運的先後阻擋通關，也不可顯示「順序反了」等提示。** 接頭寬窄不合仍不能完成。

拼圖解法與後續敘事行程分開：兩種解法都沿用既有家 → 捷運 → 街道 → 公司的劇情過場，避免行程列倒走或跳過事件。細節見 [第二天通勤路線規格](EXHIBITION_DAY_TWO_COMMUTE_ROUTE.md)。

## 甜點店小貝狗協助

### 觸發與選擇

- 只計算玩家成功滑入空格的有效移動。
- 第 12 次不提示；第 **13 次**移動後仍未接通，顯示小貝狗詢問與「要／先等等」。
- 若第 13 次正好接通，不顯示詢問。
- 選「先等等」不改盤面，後續移動不反覆自動彈出詢問。
- 玩家可再點提示區的「小貝狗幫忙」。這個入口**取代**原提示文字，不另加一行。

### 協助行為

- `solveDessertRoute` 從當下盤面用廣度優先搜尋找出最短合法解法，不直接換成固定答案盤面。
- 每 360 ms 執行一個合法相鄰滑動，只執行到解法的倒數一步。
- 最後一步由玩家完成；可移動的答案圖塊以亮框提示。
- 若原本只差一步，直接提示該圖塊。
- 協助的滑動不計入玩家移動次數；期間停用棋盤及重來，避免和動畫互相干擾。
- 重來清除移動次數、協助狀態與最後一步提示；離開關卡時清除計時器。

### 版面與完成演出

- 保留標題、玩法入口、拼圖、重來及單列提示；移除「滑動拼圖接路／自由調整」及重來圖示。
- 起終點直接使用蛋糕與公司圖塊，不疊加文字標籤；空格為淡色實線框。
- 完成後，在棋盤下方出現橫跨遊戲寬度的 72 px 橫條。
- 先顯示「完成」，1,400 ms 後切換為可點擊的「順利出發 →」，按鈕另有 220 ms 淡入。
- 出發按鈕寬度為橫條減左右各 16 px、高 48 px，使用淺色底、圓角、按壓陰影。
- 移除畫面最底部重複的出發按鈕及其整條區域。不要恢復棋盤角落小按鈕、紙卡或緞帶裝飾。
- 按出發後，保留既有 1,050 ms 成功提示，再交給原本完成回呼／事件導航。
