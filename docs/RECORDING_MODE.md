## 黃金獵犬 × 青蛙專用演出

正式版與展覽版的錄影工具列均有「專用演出」選單，可選擇「黃金獵犬 × 青蛙・拍照演出」直接開啟。

`/trial/recording/sunbeasts` 是獨立的 16:9 左右雙畫面，使用遊戲原本的捷運黃金獵犬、便利商店櫃台青蛙與抽獎券分層素材。預設整段 5.5 秒：從白畫面開始，左半背景與黃金獵犬在 0.1–0.45 秒一起出現，右半背景、青蛙與抽獎券在 0.55–0.9 秒一起出現。第 1 秒左邊開始對焦，第 1.6 秒拍照，第 3.1 秒右邊對焦，第 3.7 秒拍照；最後保留 1.8 秒讓右邊拍立得與三星完整出現，第 5.5 秒結束。

青蛙沿用便利商店的六格跳躍素材與 2.8 秒動作循環，從右往左跳，抽獎券跟隨移動。快門時間對齊青蛙落在櫃台的姿勢，調整等待／對焦時間仍能拍到主角。各自拍照後，該側浮出拍立得、照片顯影並掃過亮光，底下依序亮起三顆星；左邊的拍立得保留到右邊拍完，結尾同時展示兩張。拍立得使用快門當下的背景與角色圖層，裁切範圍與準星一致，星數固定為預告演出的三星。

「播放並隱藏工具列」直接開始乾淨演出，沒有對話或教學提示。H 叫回工具列、R 重播、Space 暫停／繼續、F 全螢幕。等待／對焦／換邊時間均可調整，按「5.5 秒預設」可回復短版節奏；時間軸可拖到任意一格查看，青蛙、拍立得顯影與星星都會停在該格，不會播放快門聲。可選擇快門音效與循環播放，背景分頁會自動暫停。沒有讀寫玩家進度或觸發收集獎勵。

## 正式版／展覽版錄影

入口：首頁的「預告錄影模式 · 16:9」，或 `/trial/recording`。遊戲右側工具欄也可直接將當前場景切進錄影模式，不會重新掛載遊戲。

1. 選擇正式版或展覽版。
2. 在場景選單選擇要拍攝的段落。沿用原本的場景跳轉與進度設定。
3. 切換「16:9 橫式」或「手機直式」，按需要取消「顯示對話 UI（含立繪）」。遊戲互動與場景內的角色／漫畫仍保留。
4. 按 F 進入全螢幕，再按 H 收起工具列，使用自己的螢幕錄影軟體開始錄製。

| 快捷鍵 | 功能 |
| --- | --- |
| H | 顯示／隱藏錄影工具列 |
| D | 顯示／隱藏對話與對話立繪 |
| F | 切換網頁全螢幕 |
| Space、Enter、→ | 推進已就緒的對話；圖片場景使用既有點擊推進 |
| Esc | 叫回工具列；全螢幕由瀏覽器處理退出 |

工具列只在畫布外顯示。比例、對話與游標選項保存在分頁的 `sessionStorage`，跨場景與重新載入保留；啟用狀態不儲存，舊版留下的 `enabled: true` 也不會自動開啟錄影。一般遊戲入口與重新載入預設為正常模式，僅從錄影入口（`capture=1`）或按「開啟預告錄影模式」時啟用。錄影工具列的版本與場景切換會明確帶入錄影入口參數，保持當次錄製連續；入口參數隨即消耗，退出或之後重新進入遊戲不會再自動套用。「退出錄影模式」回復原本的遊戲外框。錄影模式本身不重置遊戲進度。

畫布使用 852 高的邏輯座標，16:9 時向兩側擴展，再等比例縮放到可用視窗。工具列收起後，1920 × 1080 視窗會得到 1920 × 1080 畫布；其他螢幕比例會留黑邊。實際錄影解析度取決於瀏覽器與錄影軟體設定。原本的直式背景使用既有 cover／contain 規則，橫式時可能裁去上下內容，沒有自動補畫素材。需要選項、點擊物件或小遊戲的段落，仍使用原本互動；必要時按 D 顯示對話中的選項。

實作：`RecordingMode.tsx` 管理選項、快捷鍵與等比例縮放；`GameFrame.tsx` 共用錄影控制列與場景選單。各遊戲根畫布以 `data-game-viewport` 標記，錄影樣式只在啟用時生效。對話保持掛載以繼續播放打字、表情與劇情回呼，隱藏時以快捷鍵啟動當前對話的繼續按鈕。
## 預告錄影的三語版本

所有專用演出工具列新增「錄影語言」：繁體中文、English、日本語。切換後停止播放並回到起點；同一分頁切換演出與重新整理會保留語言。也可使用 `?lang=en`、`?lang=ja`、`?lang=zh` 直接開啟各版本。操作工具列維持中文，錄製的 16:9 畫面套用選定語言。

捷運的對話、角色名稱、兩個選項，小白的兩句對話，搬家日記標題與正文、傳單轉場中的日記完成畫面，以及結尾 Logo 都隨語言切換。角色名沿用展覽版的 Mugi／Shiro、ムギ／シロ。英文結尾 Logo 使用 Figma `13031:2231` 匯出的「Hibimon MOMENTS」透明原圖，保留雙行藍綠配色、白色外框及 `13031:2213` 的位置與比例；中、日文沿用原素材與尺寸。錄影專用譯文依目前已錄製的中文分鏡翻譯，保留在門口等搬家公司時聽到街上騷動的順序。

小白與捷運共用錄影時間軸的打字機：每句逐字出現，完整顯示後才亮起繼續箭頭。按三語字數配速，最晚在該句鏡頭的 65% 時完成，保留閱讀停留；暫停、倒拖、循環與更改總長都同步。原本各幕時間不變。

三語日記共用展覽版的 `buildDiaryPuzzleTextScatterSlots` 稀疏分布、跨全文分層與圖片歸位進度。英文每個字母各自一格，以 32 欄容納全文（中文字格為 16 欄），字母從散落位置跨欄、跨列移動，交換的字母保留原本延遲收整節奏。英文仍以完整單字換行；換行保留空格參與分層綁定，但不渲染空白方塊，讓同欄始終對應同一層與圖片。第二層沿用錄影版的保留列，避免撞上已還原的第一層。三語均檢查第二層全段無文字交疊與紙面溢出。

驗證：`npm run build` 通過；錄影演出測試涵蓋三語逐字完成時間、倒拖、日記範圍與 120Hz 文字碰撞檢查。`diary-puzzle-trailer.test.cjs` 共 15 項通過，另檢查共用稀疏格位、向左／右移動、跨列位移、同一單字的字母分配、每次拖曳、換行與空格還原。瀏覽器檢查英、日文小白台詞、日記完成排版、跨場景語言延續與結尾 Logo，以及英文拼圖第一層的跨欄／跨列歸位、第二層的逐字母移動。
